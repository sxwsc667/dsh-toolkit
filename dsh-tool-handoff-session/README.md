# dsh-tool-handoff-session

给 DSH 补一个 `new_work` 工具：在指定工作区开一个新会话，把交接内容作为它的第一条消息投递进去。

这个目录是本模块的唯一文档来源：实现说明在这份 README，改动历史在 `CHANGELOG.md`。
工作区的 `AGENTS.md` 只保留“进来干活要守的规矩”和指向这里的指针，不再堆实现细节。

## 怎么工作

投递出去的正文只有两块，中间不插一个字的说明：

1. **接话**：本会话最后一段有文字的助手发言原文。`session.deriveMessages()` 从后往前找
   `role === 'assistant'` 且带 `text` 块的那条；工具是在回合中间执行的，这一步的文字已经落盘，
   正好是“我刚才说到哪”。拿不到（部署不同、对象形状不同）就只发交接原文，绝不编一段冒充自己说过。
2. **交接原文**：`handoff` 本身。

总原则：**不让新会话知道这是转交过来的**。所以正文里不许出现任何元说明、会话编号、工作目录、工具名，
也不提“主会话 / 子代理”。前两版都栽在正文里解释“这段文字是谁写的”，结果新会话的注意力全被引到材料上。

- **通道**：`ctx.sessionController.create(...)` 建会话，再 `ctx.get('agents')` 取新会话自己的
  agent（智能体运行时对象），用 `agent.followup(message)` 投递。
- **来源**：`source`（来源标记）用 `{ kind: 'agent-message', form: 'relay', senderSessionId }`。
  模型看不到它，它只决定这条消息在宿主日志和界面里不算用户发言。
- **兜底**：拿不到 agent 的部署退回 `ctx.sessionController.prompt`，正文完全一致；
  第二个参数必须是中止信号，漏传会报 `throwIfAborted` 相关错误。
- **标题**：交接内容不是人类消息，宿主不会拿它自动命名会话，所以插件显式调 `rename`，
  标题取交接内容开头 18 个字。
- **限度**：模型接口上的角色只有 user / assistant / tool 三种，改不了；这段内容在会话记录里仍然是
  user 角色。插件能控制的只有来源标记和正文措辞，所以“不留痕迹”只能做到正文层面。

## 哪些模式有它

工具登记是全局的：一登记，所有会话都看得见，和会话选的是哪个模式无关。唯一的例外是极简模式（`minimal`）——只留一个人设和一条命令行，不承担交接。插件在 `agent/created` 时读会话的模式（`agent.agentPreset`），只对极简模式把 `new_work` 收窄掉（`ctx.tools.restrict`）；其他模式——标准、批量调用、框架开发、协作模式，以及以后新加的模式——一律保留。

## 交接即暂停：四条规矩

这四条写在工具描述里，是工具语义的一部分，不是建议：

1. `new_work` 只在当前对话的最后一步调用；调用之后这一轮不再分析、总结、规划，也不动文件。
2. 调用之前，把还欠用户的（要他拍板的选择、没做完的步骤、原本打算问的问题）全写进 `handoff`。
3. 调用成功之后，这一轮的回复里不许再留任何问题或待办。
4. 交接之后不跟新会话并行干活：不回头读它的消息、日志、运行结果，也不等它汇报。

理由：交接之后焦点转到新会话，在这边再问也没人答；回头去读、去等，等于把“交班”干成了
“派侦察兵回来汇报”，活还是自己在干，新会话也失去了主人位置。

另外，不再要求模型在回复末尾提醒用户切过去——界面不显示会话编号，照着找不着；用户想接着看会自己切。

## 工具描述里的两个词

- **身份 = 工作区**：面对什么事、以什么身份说话；规矩写在该工作区的 `AGENTS.md` 里，
  所以换工作区本质是换一个人、换一副立场。
- **状态 = 当下的劲头**，不是软件里的模式开关。

别退回“程序员 / 老师”这类职位举例，也别把状态说成“规划、动手、反思”几个阶段——模型会照字面理解，进而选错。

## 开发

- 三个测试脚本：`node .\test\smoke.mjs`、`node .\test\load.mjs`、`node .\test\preview.mjs`。
  最后那个会直接把实际投递出去的内容打印出来。
- 源码受宿主热重载监听：改完 `index.js` 保存即生效，不用重启。
- 改行为之前先跑一遍 `preview.mjs`，看清楚正文到底长什么样，别只看代码。
- 已知残留：早期一次失败的真实调用留下过空会话 `session-acf0ffb9`（只有会话头、没有消息），
  不影响使用；要清理的话在网页端会话列表里删掉即可。
