# dsh-tool-compact

给模型一个能自己调用的压缩工具：它判断得出「前面的上下文没用了」，就提交一次压缩，
当前这一轮说完话、会话空下来之后，较早的历史被合成一条摘要。

## 为什么要有它

DSH 自带的压缩只有三条触发路径，没有一条由模型决定：

- 自动阈值：`@deepseek-ai/dsh-compaction-basic` 在每次请求前量一次 token，
  越过 `floor(min(窗口 × 0.8, 窗口 − 输出预留 − 65536))` 才压；
- 上下文溢出：模型报 `CONTEXT_WINDOW_EXCEEDED` 后强行压一次；
- 手动命令：用户敲 `/compact`，且只在空闲时可用。

`@deepseek-ai/dsh-compaction` 的 README 明确写着「不会注册面向模型的压缩工具」，
开发备注也把「面向模型的压缩工具」列为尚未决定的事项。这个插件补的就是这一块。

光有工具不够：LangChain Deep Agents 的实测里，模型拿到压缩工具后一次都没主动用过。
所以本插件把「值得压的时机」直接写进工具描述——工具描述本身就是模型可见的提示词，
不用改系统提示。这是 Deep Agents 那篇的核心做法。

## 为什么是「提交任务」，不是立刻压缩

工具是在助手回合**中间**执行的，那时会话还占着。压缩服务有两个入口：

| 入口 | 要求 | 能否在回合中间用 |
| --- | --- | --- |
| `compactRegion(start, end, agent)` | 必须有未结束的轮次 | 能，但要自己选范围 |
| `compactNow(agent, signal)` | 必须会话空闲 | 不能，会同步抛 busy |

一开始想走 `compactRegion`，但那是「立刻压」，模型会在压完之后才继续说话，
压缩的收益要等到下一轮才体现，白白让这一轮卡一次。改成登记任务后：

- 模型调用工具时零等待，本轮照常说完；
- 真正压缩在 `agent/status` 变成 `idle` 时发生——那一刻没有驱动在跑、也没有排队；
- 压缩期间用户发的新消息按宿主原有顺序排队，等压缩落地后才开始，不会丢也不会乱序。

代价是结果没法再告诉模型（那一轮已经结束了），只能进日志。这是这个设计必须付的账。

## 它怎么工作

1. 模型调用 `compact` → 插件在内存里给这个会话记一个待办，返回「已提交」；
2. 本轮结束，宿主把状态切成 `idle` → 插件调 `ctx.compaction.compactNow(agent, signal)`；
3. 压缩服务自己选保留范围、调摘要模型、写会话记录；插件只记日志。

一切压缩逻辑都复用宿主现有后端，插件不碰摘要提示词、不碰范围选择、不写会话记录。

失败处理：压缩只在真空闲时能启动，撞上别的维护任务会抛 `busy`，这类失败多是瞬时的，
所以保留任务等下次空闲重试，最多 3 次；没有可压缩的历史时安静结束，不重试。

## 什么时候模型会用它

工具描述里写了五条「值得提交」和三条「不该提交」，摘录：

- 一段任务收尾干净、结论已定，推导过程用不到了；
- 刚读完大量材料并提炼出结论；
- 接下来要吞进大量新内容，先把旧的压掉；
- 即将进入一条很长的流程；
- 原先的结论被推翻，旧上下文只会误导。

## 怎么挂载

先把这个插件目录放到本机任意位置，比如和本仓库同级：

```
git clone <本仓库地址> dsh-toolkit
```

然后在你的 profile 的 `package.json` 里加依赖和 bundle。`link:` 后面那串换成你放插件目录的实际位置：

```json
"dependencies": {
  "dsh-tool-compact": "link:../../dsh-toolkit/dsh-tool-compact"
},
"dsh": {
  "profile": {
    "bundles": ["dsh-tool-compact"]
  }
}
```

装好依赖后重启宿主生效（`bundles` 是启动时读的，热重载改不到它）。

## 已知限制

- **结果不回流到模型**：压缩发生在回合之后，模型无法在同一轮里得知压了多少。
- **摘要格式是宿主定的**：现有模板含文件与位置、待办、当前进度、已确认结论四类信息，
  但「摘要与后续动作一致」这条校验宿主没做，本插件也没补。
- **待办表只在进程内**：宿主重启会丢掉未执行的登记。真丢了也无害，模型下一轮可以再提交。
- **只在 `idle` 触发**：如果用户再也不发消息，会话就一直停在 idle 之外的状态，任务不会执行
  ——实际上每次回合结束都会回 idle，所以正常使用中不会卡住。
